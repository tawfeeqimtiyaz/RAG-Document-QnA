# RAG Document Q&A with Groq

A Streamlit app that answers questions about your PDF research papers using Retrieval-Augmented Generation (RAG). PDFs are split into chunks, embedded locally with a Hugging Face model, and stored in a FAISS vector index. Each question retrieves the most relevant chunks, which are passed to an LLM served by Groq (`openai/gpt-oss-120b`) to generate an answer grounded in those chunks.

## Features

- Loads every PDF in a folder (`research_papers/`)
- Splits documents into overlapping chunks for better retrieval
- Local embeddings with `all-MiniLM-L6-v2` (no embedding API key needed)
- In-memory FAISS vector store, built once per session
- Answers generated by `openai/gpt-oss-120b` on Groq
- Shows the source chunks used for each answer in an expandable section

## How it works

```
PDFs in research_papers/
        │
        ▼
PyPDFDirectoryLoader  ──►  RecursiveCharacterTextSplitter (1000 chars, 200 overlap)
                                        │
                                        ▼
                    HuggingFaceEmbeddings (all-MiniLM-L6-v2)
                                        │
                                        ▼
                             FAISS vector store (in memory)
                                        │
 User question ──► retriever ──► top matching chunks
                                        │
                                        ▼
                  Groq (openai/gpt-oss-120b) with a prompt
                  that restricts answers to the retrieved context
                                        │
                                        ▼
                                     Answer
```

## Prerequisites

- Python 3.11 or 3.12 (recommended)
- A Groq API key from the [Groq Console](https://console.groq.com)
- Git (for cloning)

## Installation

1. **Clone the repository**

```bash
   git clone <your-repo-url>
   cd <your-repo-folder>/4-RAGDocumentQnA
```

2. **Create and activate a virtual environment**

   Windows (PowerShell):
```powershell
   python -m venv venv
   .\venv\Scripts\Activate.ps1
```

   macOS / Linux:
```bash
   python3 -m venv venv
   source venv/bin/activate
```

3. **Install the dependencies**

```bash
   python -m pip install --upgrade pip
   python -m pip install -r requirements.txt
```

   The first install is large because `sentence-transformers` installs PyTorch.

## Configuration

1. Create a file named `.env` in the project folder:

```
   GROQ_API_KEY=your_groq_api_key_here
```

   Do not use quotes or spaces around the `=`.

2. Add your PDFs to the `research_papers/` folder. The folder must exist next to the app file. If it contains no PDFs, the embedding step will produce an empty index.

## Usage

Run the app from the project folder:

```bash
python -m streamlit run app_huggingfaceembedding.py
```

Then open the URL Streamlit prints (usually `http://localhost:8501`).

1. Click **Document Embedding** and wait for "Vector database is ready". The first run downloads the `all-MiniLM-L6-v2` model, which can take a minute.
2. Type your question in the text box and press Enter.
3. Read the answer. Open **Document similarity search** to see the chunks it was based on.

Documents are embedded once per browser session. If you add or change PDFs, restart the app and click **Document Embedding** again.

## Troubleshooting

**`ModuleNotFoundError` for a package you installed**
Streamlit is running with a different Python than the one where you installed packages. Start it with `python -m streamlit run ...` from the activated venv, and confirm with `python -c "import sys; print(sys.executable)"` that the path points inside `venv`.

**Groq authentication error (invalid API key)**
The key in `.env` is wrong, revoked, or missing. Create a new key in the Groq Console, paste it into `.env` with no quotes or spaces, and restart the app. The `.env` file is read only at startup.

**Model not found or decommissioned**
Groq updates its model list. Check the current names at [console.groq.com/docs/models](https://console.groq.com/docs/models) and change the `model=` value in the app.

**`AttributeError: st.session_state has no attribute "vectors"`**
You asked a question before clicking **Document Embedding**. Click it first and wait for the success message.

**`File does not exist` when running Streamlit**
You're in the wrong folder. Run `cd` into the folder that contains `app_huggingfaceembedding.py`.

**Many `No module named 'torchvision'` messages in the terminal**
These come from Streamlit's file watcher scanning Transformers modules. They don't affect the app's output. To silence them, run:
```bash
python -m streamlit run app_huggingfaceembedding.py --server.fileWatcherType none
```

**Empty or poor answers**
Check that `research_papers/` contains readable PDFs (not scans without text). Scanned PDFs need OCR before they can be indexed.

**Slow answers**
`openai/gpt-oss-120b` is a reasoning model, so responses can take a few seconds longer than smaller models.

## Security notes

- Never commit `.env` or your API key.
- Never paste a real API key into code, issues, or screenshots.

Suggested `.gitignore`:

```
.env
venv/
__pycache__/
.streamlit/secrets.toml
```
